Localization

This page covers how the OCL web apps (TermBrowser v3 and the OCL Mapper) say things in each interface language. It has two parts: rules for developers, so that translated text still reads correctly once the code assembles it, and a glossary of canonical OCL terms, so every language uses the same word for the same thing in both apps.

Interface language is not content language. This page covers the UI language a user picks in the menu. It does not cover the locales of names in a terminology (a concept's locale, a repository's supported_locales), or the language the OCL AI Assistant writes in. Keep those three separate in code and in copy.

Who decides

  • Each language's terms are decided by that language's translation lead. Portuguese (Brasil): @filiperochalopes. Español and 中文: open; propose yourself in a PR.
  • Product and feature names (OCL AI Assistant, Auto Match, OCL Mapper) are decided by OCL.
  • Change this page through a pull request. A translation PR that introduces or changes a term in the glossary should update the glossary in the same PR.

Rules for developers: assembling text

Most translation bugs come from the code, not the translation: the code joins fragments that read fine alone but break once combined. The translator only sees the catalog, never the assembled sentence.

  • One key per whole sentence. Interpolate values ({{name}}) and use <Trans> for links. Never build a sentence from fragments such as please + link + or + go_to_your: word order differs between languages, and Portuguese renders that chain as "Por favor atualizar ou ir para seu Painel."
  • Pass translated labels, never raw API values. repo.type ("Collection") or a literal 'concept' inside a translated sentence renders as "este Collection" or "Este concept aparece…".
  • Don't put a gendered word next to an interpolated noun. "this {{resourceType}}" needs este or esta in Portuguese and Spanish, depending on the value. Rephrase the sentence ("a lista de {{resource}}") or use one key per type.
  • Escape once. oclweb3 does not set escapeValue: false globally (oclmap does), so a user-supplied value must pass t(key, { name, interpolation: { escapeValue: false } }). Otherwise "O'Neil" renders as O&#39;Neil.
  • Case is part of the sentence. If a fragment can start a line in one place and sit mid-sentence in another, give it two keys, or lowercase it only at the mid-sentence call site.
  • Shared keys stay identical. When a key exists in both oclweb3 and oclmap with the same English text, its translation should match in every language.
  • New English keys fall back to English until a translation lands. List the new keys in the PR description so translators can catch up.

Rules for translators

  • OCL resource names (Source, Collection, Organization…) are a per-language decision, recorded in the glossary below. The Portuguese (Brasil) rule: translate a name when a clear cognate exists (Coleção, Organização, Repositório), and keep it in English when the translation would be ambiguous. "Source" and "Sources" stay in English because "Fonte" also means font, provenance and código-fonte. Names kept in English are masculine and capitalized ("o Source", "Versão do Source"). Spanish made the other choice ("Fuente").
  • pt-BR decisions are recorded, with reasons, in ocl_issues#2878.
  • Never translate: OCL, TermBrowser, HEAD, FHIR resource names (CodeSystem, ValueSet, ConceptMap) and parameters (activeOnly, system-version…), $match, Elasticsearch, terminology names (LOINC, SNOMED CT, CIEL, ICD-10, ICD-11), and UUID, JSON, CSV, URL, API.
  • OCL AI Assistant always names OCL: "Assistente de IA do OCL", not just "Assistente de IA". Don't write "AI recommendations"; say "recommendations from the OCL AI Assistant" or rephrase. Some existing English Mapper strings still break both rules (e.g. preview_estimate_ai_*, labels that say "AI Assistant"). They'll be fixed in English and every language together, so don't treat them as precedent.
  • When a string has placeholders or sits next to a link, ask in the PR how it renders. Reviewers will quote the assembled sentence.

Glossary

Values come from the app catalogs and are shown as the base term, singular and in sentence case. For pt-BR, values follow the decisions in ocl_issues#2878; a catalog may lag until its next translation PR merges. The catalog labels themselves may be plural or Title Case. Where the two apps use different words, the note says so. Agreed means the language lead's choice is recorded. Open means a decision is pending (owner in the note). A dash means neither catalog has the term yet.
